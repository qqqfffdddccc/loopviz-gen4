# Моды LoopViz

Мод добавляет в приложение свой визуальный модуль: новую анимацию, свой MIDI-плеер, свою волну или текстовый слой. Мод лежит в отдельной папке, приложение подхватывает его при запуске и по кнопке «ПЕРЕЗАГРУЗИТЬ», пересобирать ничего не нужно.

В этой папке два рабочих примера. `example-glow-orb` рисует светящийся шар на WebGL в слоте «АНИМАЦИЯ». `example-bars` рисует скруглённые столбики спектра на canvas2d в слоте «ВОЛНА». Оба файла подробно прокомментированы, с них удобно начинать.

## Где лежат моды

Приложение читает две папки:

- `~/Library/Application Support/LoopViz/mods/`. Туда кладут свои моды. Кнопка «[↗] ПАПКА МОДОВ» в секции «МОДУЛИ» открывает её в Finder и создаёт, если её ещё нет.
- `mods/` в репозитории. Её читает только сборка для разработки (`bun run tauri dev`), в готовое приложение она не попадает.

Если мод с одним id есть в обеих папках, загрузится первый, а у второго в списке появится ошибка о дубликате.

## Структура мода

```
my-mod/
  manifest.json
  index.js
```

Каждая подпапка папки модов считается модом. Папки, имя которых начинается с точки, пропускаются. Entry-файл должен быть одним самодостаточным ES-модулем: его текст читается из файла и выполняется через blob URL, поэтому относительные импорты и импорт пакетов по имени там не работают. Если код вырос, соберите его в один файл любым бандлером (esbuild, Rollup) и укажите результат в `entry`. Библиотеку three подключать отдельно не нужно, она приходит через `api.THREE`.

Лимиты: `manifest.json` не больше 64 КБ, entry-файл не больше 8 МБ.

## manifest.json

```json
{
  "id": "example-glow-orb",
  "name": "Glow Orb",
  "slot": "hero",
  "version": "1.0.0",
  "apiVersion": 1,
  "entry": "index.js",
  "author": "LoopViz",
  "description": "Мягкий светящийся шар на WebGL"
}
```

| Поле | Обязательное | Что значит |
| --- | --- | --- |
| `id` | да | Строчные латинские буквы, цифры и дефис, 2-48 символов, начинается с буквы или цифры. Должен совпадать с `id` в `defineModule`. В реестре приложения модуль получает id `mod.<id>`, поэтому с встроенными модулями он не пересечётся. |
| `name` | да | Название в списке слота и в заглушке при падении, до 64 символов. |
| `slot` | да | Один из `hero`, `midi`, `wave`, `overlay`. Должен совпадать со `slot` в `defineModule`. |
| `version` | да | Любая строка версии, до 32 символов. Показывается в блоке «МОДЫ». |
| `apiVersion` | да | Целое число. Сейчас поддерживается `1`. Если число другое, мод не загрузится, а в блоке «МОДЫ» появится сообщение, под какую версию он написан и какую поддерживает приложение. |
| `entry` | да | Относительный путь к `.js` или `.mjs` файлу внутри папки мода, без `..`. |
| `author` | нет | Автор, до 100 символов. |
| `description` | нет | Описание, до 500 символов. |

## Контракт entry-файла

Entry экспортирует по умолчанию функцию. Приложение вызывает её один раз при загрузке и передаёт объект `api`. Функция возвращает результат `api.defineModule(meta, build)`.

```js
/** @param {import("../loopviz-mod-api").ModApi} api */
export default function (api) {
  return api.defineModule(
    {
      id: "my-mod",
      slot: "wave",
      name: "My Mod",
      surface: "canvas2d",
      params: {
        thickness: { kind: "slider", label: "ТОЛЩИНА", min: 1, max: 20, step: 1, default: 4 },
      },
    },
    () => {
      // Состояние экземпляра хранится здесь, в замыкании.
      return {
        init(ctx) {},
        resize(w, h) {},
        render(frame, params) {},
        dispose() {},
      };
    },
  );
}
```

`build` вызывается на каждый новый экземпляр. Превью и экспорт создают свои экземпляры независимо, поэтому переменные уровня модуля становятся общими для обоих и портят результат. Всё, что меняется от кадра к кадру или хранит ресурсы, держите внутри `build`.

Методы экземпляра:

- `init(ctx)`. Один раз при создании. `ctx` зависит от `surface`, см. ниже. Может вернуть Promise.
- `resize(w, h)`. Зона изменила размер в пикселях. Поверхность к этому моменту уже изменена.
- `render(frame, params)`. Рисует один кадр. `params` содержит текущие значения параметров из инспектора.
- `prepare(params)`. Необязательный метод. Экспорт ждёт его перед первым кадром, превью не ждёт. Подходит для загрузки шрифтов и картинок.
- `dispose()`. Освободите материалы, текстуры, геометрию и всё остальное, что создали.

### Что лежит в `api`

| Член | Что это |
| --- | --- |
| `API_VERSION` | Версия контракта, число. |
| `defineModule(meta, build)` | Собирает определение модуля. |
| `THREE` | Тот же экземпляр three, которым рисует приложение. Свою копию three подключать нельзя: материалы и текстуры от неё не заработают с общим renderer. |
| `clamp`, `lerp`, `smoothstep` | Числовые помощники. |
| `srgbToLinear`, `linearToSrgb`, `linearToCss(rgb, alpha?)` | Цвета. Цвета темы лежат в линейном RGB, для canvas2d их нужно превращать в строку через `linearToCss`. |
| `glsl.noise` | Кусок GLSL с `hash12`, `hash22`, `gnoise(vec2, perY)`, `fbm(vec2, perY, octaves)` и `rot2`. Вставляйте в начало фрагментного шейдера. Параметр `perY > 0` замыкает шум по вертикали. |
| `glsl.fullscreenVertex` | Вершинный шейдер для полноэкранного прохода, отдаёт `varying vec2 vUv`. То же самое лежит в `ctx.helpers.fullscreenVertex`. |
| `fonts` | Список шрифтов, которые поставляются с приложением: JetBrains Mono, IBM Plex Mono, Space Mono. |

Типы всего перечисленного лежат в `mods/loopviz-mod-api.d.ts`. Подключить их в JS можно комментарием JSDoc, как в примерах, а в TypeScript обычным импортом типов.

## FrameInput

Объект `frame` приходит в `render` на каждом кадре.

| Поле | Значение |
| --- | --- |
| `t` | Секунды от начала ролика. |
| `loopT` | Секунды от начала выбранного фрагмента, от 0 до длины фрагмента. |
| `beat` | Дробная доля такта по времени исходника. |
| `bar` | Дробный номер такта по времени исходника. |
| `bpm` | Темп. |
| `audio.rms` | Громкость, 0..1. |
| `audio.onset` | Сила удара, 0..1. |
| `audio.bands` | `Float32Array` из 8 логарифмических полос, 0..1. |
| `audio.spectrum` | `Float32Array` из 64 логарифмических полос от 30 Гц до 16 кГц, 0..1. |
| `midi.active` | Ноты, которые звучат прямо сейчас. |
| `midi.window` | Ноты в окне от `loopT - lookbehind` до `loopT + lookahead` с учётом зацикливания фрагмента. |
| `midi.range` | `[минимальная, максимальная]` высота нот в треках. |
| `midi.lookbehind`, `midi.lookahead` | Размер окна в секундах назад и вперёд. |
| `wave.peaks` | `Float32Array` пар `[min, max]` по всему файлу, длина равна удвоенному числу точек. |
| `wave.progress` | Позиция исходника в файле, 0..1. |
| `wave.fragment` | `{ start, end }` границы выбранного фрагмента в тех же долях файла. |
| `theme` | `bg`, `ink`, `accent`, `accentGlow` (линейный RGB, тройки 0..1), `grain`, `glow`. |
| `size` | `{ w, h, dpr }` размер кадра. В экспорте это размер выходного видео, в превью размер окна. |

Нота (`NoteEvent`): `pitch`, `velocity` (0..1), `start`, `end` (секунды на часах лупа), `track`.

Размеры в пикселях задавайте в долях от `frame.size.h`. Тогда превью и экспорт в 4K выглядят одинаково. Встроенные модули считают от высоты кадра 1920 пикселей: `unit = frame.size.h / 1920`.

## Параметры (ParamSchema)

Поле `params` в `meta` описывает параметры. Инспектор справа строит контролы по этой схеме сам, React-код писать не нужно. Ключ параметра должен быть латинским идентификатором, параметров не больше 32. В `render` значения приходят в объекте `params` под теми же ключами.

| `kind` | Поля | Значение |
| --- | --- | --- |
| `slider` | `label`, `min`, `max`, `step`, `default` | Число. Нужно `min < max`, `step > 0`, `default` внутри диапазона. |
| `color` | `label`, `default` | Строка `#rrggbb`. |
| `select` | `label`, `options`, `default` | Строка из `options`. |
| `toggle` | `label`, `default` | Булево значение. |
| `font` | `label`, `default` | Имя шрифта из выпадающего списка шрифтов приложения. |
| `text` | `label`, `default` | Строка. |
| `image` | `label`, `default` | Data URL картинки или пустая строка. Инспектор даёт выбрать файл. |

Если схема не проходит проверку (неизвестный `kind`, `default` вне диапазона, цвет не в формате `#rrggbb`), мод не загрузится, а причина появится в блоке «МОДЫ».

## Детерминизм

Экспорт рендерит кадры строго по порядку, и один и тот же кадр обязан получаться одинаковым при каждом запуске. Из этого следует правило: результат `render` должен зависеть только от `frame`, `params` и состояния, которое вы сами обновляете фиксированным шагом.

- Время берите из `frame.t`, `frame.loopT`, `frame.beat` или `frame.bar`.
- Случайные числа получайте из хеша от координат или индекса, например через `hash12` из `api.glsl.noise`. `Math.random()` и `Date.now()` в `render` использовать нельзя.
- Если нужна физика или частицы, шагайте состояние с фиксированным `dt` (например 1/60 секунды) от кадра к кадру и начинайте с одного и того же начального состояния. Превью может перескакивать назад по времени, поэтому для надёжности пересчитывайте состояние из `frame.t`, а не копите его бесконечно.
- Асинхронные ресурсы (шрифты, картинки) загружайте в `prepare`, чтобы к первому кадру экспорта они были готовы.

## Поверхности: webgl и canvas2d

Поле `surface` выбирает, что получит `init`.

**webgl.** `ctx.surface === "webgl"`. У вас есть общий `ctx.renderer` (THREE.WebGLRenderer), собственный `ctx.target` (WebGLRenderTarget) и `ctx.helpers.renderFullscreenPass(material)`, который рисует материал на весь target. Типичный мод создаёт `ShaderMaterial` с `ctx.helpers.fullscreenVertex` и своим фрагментным шейдером, а в `render` обновляет uniforms и вызывает `renderFullscreenPass`. Выводите цвет и альфу покрытия без премультипликации и ставьте `blending: THREE.NoBlending`: compositor сам положит слот на бумагу. Состояние renderer за пределами своего `render` менять не нужно.

**canvas2d.** `ctx.surface === "canvas2d"`. У вас есть `ctx.canvas` (OffscreenCanvas) и `ctx.ctx` (его 2D-контекст). Перед каждым `render` холст очищается, поэтому рисуйте кадр целиком. Размер холста равен размеру зоны в пикселях.

## Как перезагрузить мод

1. Измените файлы мода.
2. Откройте секцию «МОДУЛИ», подблок «[+] МОДЫ» и нажмите «[↻] ПЕРЕЗАГРУЗИТЬ».

Приложение удалит старые определения модов из реестра, заново прочитает папки, выполнит entry (каждый раз как новый blob URL, поэтому кэш не мешает) и пересоздаст экземпляры в слотах, где выбран мод. Значения параметров сохраняются: новые параметры получают `default`, исчезнувшие и значения не того типа отбрасываются.

## Как отлаживать

- Блок «МОДЫ» показывает `[●] название версия (слот)` для загруженных модов и `[ ] id` с текстом ошибки для тех, что не загрузились. Ошибки бывают в манифесте, в синтаксисе entry, в форме определения (не совпал id или slot, плохая схема параметров) и в выполнении `default(api)`.
- Если мод падает в `init`, `resize` или `render`, приложение отключает этот экземпляр, один раз пишет ошибку в консоль и рисует на месте слота тонкую рамку с надписью `МОДУЛЬ УПАЛ: <название>`. Превью продолжает работать. В блоке «МОДЫ» у мода появляется строка с этапом и текстом ошибки до следующей перезагрузки.
- Экспорт заглушки не терпит: если мод упал во время экспорта, экспорт останавливается с сообщением вида «Модуль «Название» упал на этапе render: текст ошибки». В готовый ролик пустой слот не попадёт.
- Консоль разработчика (в `bun run tauri dev` открывается правой кнопкой по окну, пункт Inspect Element) показывает `console.log` из мода и полный стек ошибки.
- Dev-автотест `LOOPVIZ_AUTOTEST_MODS=1 bun run tauri dev` загружает все моды, рисует каждый несколько кадров и печатает по строке на мод (`ok` или `ОШИБКА`). Код выхода 0 означает, что всё загрузилось и отрисовалось.
- В обычном браузере (`bun run dev` без Tauri) моды недоступны: приложению нужен доступ к файлам, и в блоке «МОДЫ» об этом написано.

## Файл типов

`mods/loopviz-mod-api.d.ts` ведётся вручную по `packages/mod-api`. Тест `packages/engine/src/mods/author-types.test.ts` сверяет его с кодом: версию API, список слотов и видов параметров, поля `FrameInput`, состав `api`, и проверяет типами оба примера. Если вы меняете контракт в `packages/mod-api`, тест напомнит обновить файл.
